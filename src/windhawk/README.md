# Dynamic Cursor Windhawk Mod

This directory contains the Windhawk mod implementation for Dynamic Cursor. The mod injects into target Windows applications to intercept cursor updates and apply hardware cursor state transitions directly within application window threads.

## Architecture & Mechanics

The Windhawk mod intercepts calls to `user32!SetCursor` using Windhawk function hooking APIs (`Wh_SetFunctionHook`). When an application invokes `SetCursor`, the hook evaluates the active composite cursor state generated by the shared `dynamic-cursor` core engine.

If a composite cursor is active, the hook substitutes the custom cursor handle. When no custom state is asserted, the hook delegates directly to the original `user32!SetCursor` implementation. This mechanism works alongside the standalone system tray daemon or as an independent in-process actuator.

## Configuration Settings

The mod exposes configurable parameters in the Windhawk user interface:

| Setting Key | Type | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PipeName` | String | `\\.\pipe\dynamic_cursor` | Path of the IPC named pipe used for layer streaming and state synchronization. |
| `DefaultTint` | Integer | `0` | Default 32-bit ARGB hex integer used to procedurally tint the hardware pointer shape. |

When `DefaultTint` is non-zero, the mod initializes a tinted base arrow cursor on module startup.

## Installation

### Method 1: Windhawk UI

1. Open the Windhawk application window.
2. Navigate to the **Advanced** tab and select **Create Local Mod**.
3. Set the Mod ID to `dynamic-cursor`.
4. Copy the entire contents of [`dynamic-cursor.wh.cpp`](./dynamic-cursor.wh.cpp) into the Windhawk code editor.
5. Click **Compile Mod** to verify compilation and activate the mod.

### Method 2: Manual Mod Directory Deployment

1. Locate the Windhawk local mods directory at `%ProgramData%\Windhawk\Engine\Mods`.
2. Place `dynamic-cursor.wh.cpp` into the mods directory.
3. Reload Windhawk engine configuration to detect and compile the new mod.

## Standalone Daemon Coexistence

The Windhawk mod functions as a per-process hook layer. When running alongside the standalone `dynamic-cursor-tray.exe` daemon, the daemon updates the system-wide cursor plane via `SetSystemCursor`. The Windhawk mod ensures processes that frequently re-assert local cursor shapes respect the composite state without cursor flicker.
